# 蓝色大肥鱼 · 动画状态与频率

先根据 dsh 的真实事件确定当前状态，再从该状态允许的动画中选择。角色和指令框不增加状态栏，输入框仍只有一栏。

## 工作状态

| dsh 正在做什么 | 蓝色大肥鱼的动作 | 判断来源 |
|---|---|---|
| 思考、准备下一步 | 新动画的思考片段播放一遍 → 正常待机动画轮播 | 进入思考时触发一次；同一思考状态不重复，有真实进展再切换工作动作，帧率不变 |
| 读取文件、列目录、查看图片 | 好奇观察 / 安静注视 | read、view、list 等读取工具；编辑器的 view 命令 |
| 搜索资料、网页或文件 | 好奇查找 / 安静注视 | search、web_search、web_fetch 等工具 |
| 写入、修改文件 | 新动画的打字片段 | write、edit、apply_patch；编辑器的 create / str_replace / insert |
| 执行程序、构建、终端命令 | 打字操作 / 安静注视 | bash、pwsh、exec_command、run_code 等；简单只读命令归为读取 |
| 输出回复 | 打字 / 微笑 | 文本回复流，且没有仍在运行的工具 |
| 委派工作或等待子任务 | 纸飞机 → 躺下等待 | subagent、spawn_agent、wait_agent 等委派工具 |
| 等待许可、等待回答问题 | 探头等待 / 安静注视 | approval/asked、ask_user_question |
| 请求重试 | 思考 / 安静等待 | 可恢复的请求错误或工具失败 |
| 服务繁忙、限流 | 举“服务器繁忙”牌 / 思考等待 | 请求错误中的 429、503、rate limit、overloaded |
| 完成 | 灵光一闪 / 开心跳跃 / 微笑 | 当前回合明确完成 |
| 失败 | 轻哼 / 难过表情 | 明确的回合失败或 agent 错误 |
| 取消、停止、离线 | 返回日常待机 | 回合中断或连接断开 |

权限和用户问题优先于工作状态；多工具同时运行时，依次优先显示修改、执行、委派、搜索、读取。工具结束后根据其调用编号清除状态；回复流不能覆盖仍未结束的工具。历史回放不会再次庆祝，短暂请求错误也不会被当成最终失败。无法识别的工具使用中性的观察动作。

每约 2 秒用 dsh 的真实运行状态和最新事件位置校准当前会话，避免漏掉结束事件后一直停留在思考。旧快照和其他会话的状态不会覆盖当前状态；刚收到的回复流也不会被同一事件位置的普通思考快照覆盖。接入时读取正在输出的流，运行停止但缺少结束证据时回到待机，不播放无依据的完成庆祝。

工作状态相同期间，动画通常保持 10–18 秒后才考虑轮换；连续收到文本或推理片段不会从头重播。只有一种合适动画时继续循环。拖动、打开菜单、投喂或手动选择动作期间，会保留当前互动，结束后再接回工作动画。自动待机动作可被工作状态接管。庆祝最多等待 20 秒，过时的完成提示不补播。

## 日常动作不会被散步挤掉

活泼陪伴中，随机动作之间留出 7–13 秒的待机间隔（平均从上一版 16 秒缩至 10 秒），启动后首次为 4–8 秒；一次动作播放完才计入接下来的待机时段。散步的待机间隔为 50–85 秒，到期更早的动作先执行。安静陪伴暂停这些自动行为，手动互动和对话反应仍有效。

每次散步走约 2.5–6 秒，然后播放对应方向的撞倒在地动画，完整收尾后恢复待机。散步时限按真实经过时间计算，菜单暂停不计入；结束最多等待一个步行动画周期，不会因界面卡顿或遗漏某一帧无限延长。工作状态更新会等待散步和摔倒收尾，再接回最新工作动作。

触发间隔与播放速度分别控制：动画仍按素材原始帧率、真实经过时间以 1 倍速播放，未缩短动画段或加速动作。已核对原始素材包中 65 个共有动画的帧率一致；新加入的写代码和摸尾巴允许动画均保持原有 10 fps。界面刷新间隔只控制重绘，不改变动画时间。

## 吃饱和屏幕游泳

投喂后饱腹度达到 100%，先完整播放吃饭或吃鲷鱼烧，再播放“吃饱揉肚子”：站着摇晃、坐下、躺下揉肚子、举手说吃不下了，最后揉肚子和打瞌睡。97 帧的前段播放一次，65–96 帧再播一轮，总计约 12.9 秒，然后恢复正常待机；不会因为仍然很饱而一直占用动作。未吃满的鲷鱼烧仍接开心跳跃。素材采用无气泡版本，第 35 帧和第 51 帧由应用显示“嗝…好撑”“吃、吃不下了…”，遵循气泡开关。

完整尺寸游泳的两个 ZIP 是一套互补素材：主卷含朝右、转向、朝右跃出；第二卷含朝左和朝左跃出。合并后保留 384×576 原始画布，按站姿可见高度统一以 2/3 比例绘制，防止角色突然变大或跃出水面时裁切、拉伸。运行时只使用和平时角色同尺寸的完整素材，保留原始 10 fps；小尺寸原始帧仅留作素材存档，不进入动作菜单或随机池。新增共 257 张原始透明 PNG，可通过 `assets/extra/additions.json` 的逐帧 SHA-256 核对。

日常动作池仅选中正常尺寸游泳，权重为 0.8，冷却 95 秒并参与轮换补偿。保持当前横向位置开始，在原站位略上方横向游约 14–22 秒，碰到边缘先播两帧转向，再从游泳第 2 帧继续。**只有点击才跃出水面**，单击或双击均只安排一次；在当前循环结束时接上跃出片段，最多等待 1.8 秒，2 秒跃出片段播放完，从同一方向的游泳第 1 帧继续。游泳期间不会自动跃出，反复点击也不延长出游时限；结束后约 1.2 秒回到地面，恢复正常角色画布和待机。

右键「动作」可播放“屏幕游泳”“吃饱揉肚子”。「自由游泳」开关只控制自动出游，关闭时结束当前游泳；安静陪伴也暂停自动出游。拖动或选择其他手动动作可打断游泳，菜单打开期间暂停计时，缩放和显示器变化后保持在屏幕内。dsh 工作动画和对话表情等待游泳收尾，对话回复气泡仍显示在可见角色身旁，字体增大为 17 像素。输入框可用 `/游泳`、`/停止游泳` 离线控制。

| 待机动作 | 相对权重 | 同一动作最短冷却 |
|---|---:|---:|
| 挥手 | 1.0 | 45 秒 |
| 伸懒腰 | 1.0 | 60 秒 |
| 行礼 | 0.9 | 60 秒 |
| 泡茶 | 0.8 | 60 秒 |
| 好奇观察 | 1.0 | 45 秒 |
| 跳舞 | 0.7 | 75 秒 |
| 坐下 | 0.8 | 65 秒 |
| 傲娇得意 | 0.7 | 75 秒 |
| 偷偷探头 | 0.7 | 55 秒 |

权重决定大致比例，不是每次独立抽签。选择器累计各动作错过的合格机会，让长期没播到的动作逐渐获得优先级；错过两轮后优先安排，但仍遵守场景和冷却。最近两种动作在有其他合适候选时不再重复；泡茶和喝茶还共享一组冷却，防止茶相关动作挤占其他动作。手动播放也计入待机冷却。

完成时的“灵光一闪”冷却 45 秒，开心跳跃冷却 30 秒；冷却中用微笑等轻反馈，连续短任务不会一直庆祝。失败时的轻哼冷却 90 秒。

讨饭改为间隔 60–100 秒，求关注在第一次触发后间隔 150–240 秒，鼠标悬停求关注冷却 90 秒。睡眠同时参考用户操作角色和鼠标活动，正常使用电脑时不会仅因长时间没有点击她而自动睡着。

## 对话表情和动作

常见词先触发本地反应，命中后不请求模型判断表情。“你是谁”“现在几点”“今天想吃什么”等完整、中性的问句直接保持默认，不请求表情判断；带额外情绪或任务内容的句子不适用这条规则。其他没有命中的输入，表情判断单独请求模型，与聊天回复并行；回复先发起，气泡不等待分类结果。分类只读取当次输入，不含聊天历史、长期记忆或任务资料，不使用工具，关闭思考、最多输出 32 token。默认 none，普通聊天、无明显情绪变化时继续原有表情和动作。模型只能选择固定分类，不能指定任意动画、运行命令或改变工作状态。

| 对话举例 | 反应 |
|---|---|
| 大笨蛋、你个小笨蛋 | 脸红轻哼 |
| 你真可爱、喜欢你 | 害羞 |
| 你好厉害、真棒 | 得意 |
| 早安、你好、再见 | 挥手 |
| 谢谢你、辛苦啦 | 行礼 |
| 我好难过、好累 | 关切的难过表情 |
| 好耶、太好了 | 开心跳跃 |
| 猜猜我带了什么 | 好奇 |
| 吓你一跳 | 惊讶 |
| 摸摸、摸头、摸一下你的尾巴 | 摸头 / 原有摸尾巴完整互动 |
| 跳个舞、来喝茶、伸个懒腰、给我饼干 | 跳舞 / 喝茶 / 伸懒腰 / 给饼干 |

另有微笑、探头、哭哭，共 18 种反应。关键词避开否定、引用和明确的任务语境；例如“你不是笨蛋”“把大笨蛋写进文件”不会直接触发生气。模型只判断当前输入，工作指令默认 none；工作意图确认后取消尚未返回的表情判断，主动进度汇报不发起表情分类。

同一种反应至少间隔 6 秒，跳舞、喝茶等为 10 秒，摸尾巴为 15 秒；所有反应之间至少间隔 1.8 秒。关键词已触发时，模型不会重播或换成相反表情。拖动、投喂、摸尾巴、睡眠、落地以及菜单操作受到保护，待播反应最多等待 6 秒，过期或用户开始新互动就丢弃。结束后自然恢复当前真实工作动画；分类超过 10 秒或新对话已经开始时不补播，失败静默保持原动作。

集中关键词与素材映射在 `app/conversation_reactions.py`，独立模型分类在 `app/dsh_plugin/companion-chat.mjs`，简短性格提示在 `app/dsh_plugin/persona.md`。

## 情境专属动画

吃饭、偷吃 token、摸尾巴、摸肚子、叫醒、被连续戳、拖动与落地仍使用各自条件。摸尾巴新增 60 帧允许动画，接在甩尾巴后；等待约 4 秒，点击她播放确认分支，未点击播放超时分支。菜单和独立模式「摸尾巴」指令也能触发，工作联动会保留这次手动互动。它们不参与待机轮换补偿，避免读文件时吃饭或正常工作时假装服务器繁忙。带饭碗幻想的旧“深度思考”和“震惊瘫坐”保留在玩耍菜单；工作思考使用新加入的思考片段。“外包然后睡觉”用于真实委派状态，也保留手动互动。

公平性只作用于当前场景中符合条件的动画；没有投喂、子任务或失败等事件时，不会为了凑次数制造这些情境。右键的互动、玩耍和动作菜单可以主动播放相应素材。

## 本轮验证

- 对话反应更新：44 项回归检查通过；涵盖关键词、独立分类并行、普通话语保持默认、晚到结果丢弃、完整摸尾巴队列保护和工作动画恢复。四种典型反应使用应用实际渲染检查，保留原始素材。
- 本机独立分类联调：聊天回复先发起，分类不阻塞气泡；普通问句返回 none，明显情绪映射到现有表情，不创建 Harness 任务。性格精简后多轮回复未固定用“哼”开头。

- 177 步完整互动自检通过；11 项原有回归、5 项 dsh 流程、8 项状态与频率测试通过。
- 10 个随机种子各模拟两小时，每 20 秒提供一次合格待机选择机会；13 种待机动作全部出现，每种 14–39 次，没有最近两种重复或冷却违规。该结果验证选择器分布，不代表实际桌面每两小时的播放次数。
- 本机 dsh 实测：从单行指令框创建测试会话、发送指令、收到回复、播放完成动画。另一次联调通过真实 read / edit 工具修改专用测试文件，观察到读取 → 修改 → 完成的状态切换。

集中规则在 `app/animation_policy.py`，调整权重、冷却及状态动画池可在这一处完成。
