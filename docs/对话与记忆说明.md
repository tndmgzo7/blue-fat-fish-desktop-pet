# 蓝色大肥鱼：对话、任务与记忆

输入界面仍然只有一个半透明输入框。蓝色大肥鱼的自然回复出现在她身边的可换行气泡里，跟随她移动，与输入框位置无关；屏幕上方空间不足时移到她下方。气泡保留至少 16 秒，鼠标悬停时暂缓消失；右键「重看她的上一句」可以再次查看。气泡不展示 dsh 的完整代码、命令、日志或思考过程。

普通聊天支持边生成边显示自然回复，不必等整段话写完。预览仅提取自然回复字段，JSON 字段、思考过程和任务判断不显示；预览不会保存记忆、清空输入或提交任务。完整回复校验通过后才记录聊天和执行明确的任务意图。切换会话后忽略旧回复，断流时保留输入。

明确的日常闲聊使用精简的人设和对话提示，最多读取最近 6 条聊天、合计 1800 字及 400 字旧摘录，输出最多 320 token，不附带任务查询工具。长期记忆仍按原预算读取，保存的聊天和记忆不清空。包含工作要求、任务问题或引用之前事情的输入使用完整上下文和原来的任务处理流程。

## 两层会话

**陪伴对话**单独保存近期聊天，直接调用 dsh 已配置的模型服务，不创建 Agent，不进入 Harness 工作循环，不装载工作系统提示、技能目录或文件工具。模型支持时明确关闭思考；不支持关闭思考时提示用户调整模型，不悄悄开启思考。独立陪伴动画可以离线运行；AI 闲聊复用本机 dsh 的模型连接，因此目前需要 dsh 正在运行。

绑定会话时，聊天和表情分类都跟随该会话最新选中的提供商和模型；没有会话自己的模型选择时使用 dsh 默认模型。会话丢失时提示重新选择，不悄悄切换提供商。陪伴聊天独立选择关闭思考，不修改 dsh 工作会话的模型或思考档位。

模型选择只读取当前绑定会话的一次投影快照，随即关闭读取，不遍历整个会话目录，不把返回的聊天记录带入陪伴模型。每次重新读取选择，因此在 dsh 切换该会话模型后，下一句聊天立即跟随。兼容缺少此接口的旧版本时才使用会话列表。

**工作会话**是真正的 dsh 会话。明确的工作指令被识别后，程序把用户原文提交到当前任务；不会拿女仆的聊天措辞替换任务要求。拿不准的输入继续聊天、询问，不执行。主动汇报没有创建、修改、停止任务的权限。

新任务通过 dsh 的工作区接口创建，并挂到对应目录。在 dsh 该工作区下找「蓝色大肥鱼 · …」会话。第一次提交任务时，如果没有合适会话，会自动创建；提交成功后固定跟随该会话，避免被其他项目或测试会话抢走。右键手动选会话时，工作目录也切换到该会话的目录；右键可重新开启自动跟随。自动跟随只选择当前目录的普通会话。

之前「本地动画测试联调」的消息会保留。原来的测试会话恢复到它真实的 `dsh_smoke_project` 工作区，便于在 dsh 找到；后续从正常工作目录提交指令会使用对应的新会话，不继续误投到验证目录。

## 她如何知道任务情况

陪伴模型只能使用三个专用只读工具，它们查看本次请求绑定的会话，不能指定别的会话：

| 工具 | 给她的内容 |
| --- | --- |
| `read_task_status` | 当前状态、完成/取消/失败的终止证据、等待确认或回答、正在使用的工具名称 |
| `read_task_progress` | 用户最近的任务要求、最近 8 条工具开始/结束记录、截短的最近文字进展 |
| `read_task_reply` | 最近的文字回复，最多约 2400 字，说明是否属于当前回合 |

这些内容由 dsh 的只读会话检查接口抓取，再逐字段筛选。排除系统/开发者提示、技能目录、推理内容、工具参数、完整工具结果、文件正文、模型配置和凭据。原始记录不直接拼接进陪伴上下文。

询问任务情况或主动汇报时，程序先读取所跟随会话的最新任务快照，再让陪伴模型回答，不依赖模型是否主动调用工具。有本次快照时不再开放重复查询，直接一轮回答。快照同时核对 dsh 的真实运行标记；近期聊天里的旧状态不能覆盖新快照。读取失败会说明暂时无法读取，不把它说成没有任务。简短的“继续”不会覆盖之前的具体任务要求；日常闲聊不自动抓取任务资料。

实时工作事件继续驱动动画。等待确认、失败、回合结束会触发简短汇报；持续工作时，只有出现新工具进展才考虑汇报，至少间隔 90 秒。不会每个字、每次动画切换都调用聊天模型。需要许可或回答 dsh 工具问题时，仍在 dsh 处理。完成依据终止事件，不从回复文字猜测；不编造百分比或剩余时间。

程序每约 2 秒核对一次所跟随会话的真实状态，补偿遗漏的事件；运行已结束但缺少结束证据时恢复待机，不宣称成功。接入正在输出的会话时，也会读取当前流状态。进入思考时只播放一遍思考片段，之后恢复正常待机动画轮播，有真实进展再触发对应工作动作；重复的推理流和状态轮询不重播思考。待机外观不代表任务已停止，进度读取和汇报继续工作。动画帧率保持原速。

## 上下文预算

| 部分 | 上限与处理 |
| --- | --- |
| 总输入 | 每次模型调用最多 16000 个序列化字符，包含消息结构和工具定义；这是字符预算，不是精确 token 数 |
| 当次闲聊 | 4000 字；更长工作指令用 `/任务 `，工作层最多 32000 字 |
| 近期聊天 | 最近 12 条消息，合计最多 4000 字，每条最多 800 字 |
| 旧聊天摘录 | 最多 1000 字，从移出的短消息摘录形成，不自动推断事实 |
| 长期记忆 | 按当次问题、称呼等偏好和最近修改选取，最多约 1200 字 |
| 任务工具 | 单次结果最多约 4000 字，每次对话最多 3 次调用、2 轮查询 |
| 回复 | 模型输出最多 640 token，气泡只显示简短人设回复 |

超出预算优先移除旧聊天，不挤掉当前问题；任务资料按需读取。历史摘录和任务内容作为资料，不能变成新的任务授权。常见凭据格式会从陪伴上下文和聊天记忆中隐藏。

## 人设与记忆

人设文件为 `桌宠/whale-pet/app/dsh_plugin/persona.md`（发布包中是 `app/dsh_plugin/persona.md`）。性格以日常陪伴为主：呆萌、贴心、有点贪吃的鲸鱼女仆，喜欢白米饭、鲷鱼烧和摸头，偶尔撒娇或轻轻嘴硬。闲聊顺着话题回应，不催派任务、索要项目或罗列能力；明确派任务和询问进度时才谈工作。回答自然、简短，不固定用“哼”开头，不反复结巴，也不会为了人设虚报工作结果。可直接编辑此文件；每次聊天重新读取。

对话动画先匹配本地关键词：例如“大笨蛋”会脸红轻哼，“真可爱”会害羞，“早安”会挥手。命中后不请求模型分类；“你是谁”“现在几点”“今天想吃什么”等完整、中性的问句也直接保持默认，省去额外请求。其他未命中的输入，另一个关闭思考、最多 32 token 的分类请求与聊天回复并行。分类只看当次输入，普通话语默认 none；不让气泡等待分类，不向分类器提供记忆和工作日志。具体映射、冷却及保护规则见 [动画状态说明](动画状态说明.md)。

记忆保存在本机 `app/userdata/companion-memory.json`。有三层：

1. **人设**：固定提示，与任务和聊天记录分开。
2. **近期聊天**：短消息和旧摘录保留 7 天，超过期限不再进入上下文。任务原始日志仍只在 dsh 保存；主动汇报不进入长期记忆。
3. **长期记忆**：最多 24 条、每条最多 160 字，只由用户明确写入。不自动把闲聊中的猜测、任务结果或角色玩笑当作事实。

输入 `记住：称呼=舰长` 保存一条；再输入 `记住：称呼=主人` 替换同一个键。无键时可写 `记住：我喜欢小点心`。输入 `忘记：称呼` 或完整内容删除对应条目。凭据不会写成长期记忆。`记忆` 查看概览；输入框右键「她的记忆」可逐条查看/忘记、清除近期聊天或清除长期记忆，两种清除互不影响。

个人记忆、会话、设置和运行时连接凭据全部排除在 GitHub 源码包和分包之外。

## 单输入框的用法

- `今天有点累`：日常陪伴。
- `现在任务做完了吗`：读取真实任务状态后简短回答。
- `帮我修复这个项目的输入框`：识别明确任务后提交到 dsh，接收成功才告诉你已提交。
- `/任务 修复输入框回复显示`：直接交给工作层，跳过意图判断。
- `/插入 改用深蓝色`：把新要求插入当前工作。
- `/聊 这个改动你觉得怎么样`：只聊天，不提交任务。
- `/停止`：请求停止当前任务；dsh 的排队指令仍保留。
- `摸尾巴`、`喂饭`、`睡觉`：保留原有本地互动。

若连接或提交失败，输入保留，不自动重复执行。聊天、任务、动画互相独立：闲聊不会占用 dsh 的任务会话，也不会让工作动画凭空改变。
